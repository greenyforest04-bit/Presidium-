# Presidium: аккаунты и сеансы

Рабочая ветка: `feature/matrix-account-sessions`. Состояние до изменений сохранено в
`presidium/.cache/auth-baseline-20261016-214849/`: рабочие файлы, оба Git diff,
копия индекса и согласованная SQLite-копия продуктовой базы. Пользовательские
изменения и существующий staging не сбрасывались. AGENTS.md в проекте и его
родительских каталогах не найден.

## Проверенная исходная архитектура

- Главный frontend: Next App Router, `presidium/web/app/page.tsx`, оригинальные
  компоненты Аргона. Старый Vite-интерфейс не обслуживает `/`.
- API: FastAPI `presidium.api:app`, порт 8000. Бизнес-функции используют
  существующий Node-модуль и SQLite `.data/product/product.sqlite3`.
- Чат: Tuwunel на 8008, Matrix JS SDK и Rust Megolm в браузере. Пользователь —
  неизменяемый Matrix MXID; локальный продукт использует этот же ID.
- Пароли и уникальность логина принадлежат Matrix/Tuwunel (Argon2id, RocksDB
  в существующем Docker volume). Второй базы паролей и другого транспорта нет.
- История чатов остаётся на Matrix; ключи — в существующем Rust IndexedDB.
  Заметки/черновики/медиа приложения используют исходную IndexedDB и
  пространства аккаунтов. Локальные Matrix-сообщения не копируются в другую БД.
- Найденный дефект: прежняя «смена аккаунта» удаляла cookie без Matrix logout;
  прежний список устройств отражал продуктовые сессии, а не отзыв Matrix.

## Реализуемая модель

- `/api/auth/*` — граница браузера, `/v1/auth/*` — серверные операции.
  Matrix выдаёт отдельный токен и device ID каждому устройству. Cookie
  `presidium_matrix_token`: HttpOnly, SameSite=Strict, Path=/api, Secure для HTTPS.
- SDK получает собственный Matrix-токен через same-origin bootstrap; токен нужен
  браузеру для E2EE. Новые токены не сохраняются в localStorage. Это не защита
  от исполнения вредоносного JS в origin; HttpOnly защищает cookie от прямого чтения.
- `auth.sqlite3`: только отпечатки Matrix-токенов, MXID/device ID, фиксированное
  время истечения/отзыва, устойчивые лимиты попыток и журнал создания аккаунтов. Учётных записей и паролей
  в ней нет. Схема создаётся аддитивно, прежние миграции не редактируются.
- Логин: trim + ASCII lowercase, 3–64 символа `[a-z0-9][a-z0-9._=-]{2,63}`.
  Проверка на сервере и в форме. Перед обращением к Matrix логин резервируется
  в `registration_jobs` с PRIMARY KEY(login), сериализующим создание между
  серверными процессами. Это необходимо: живой конкурентный тест Tuwunel 1.9.3
  обнаружил два успешных ответа для одного имени при прямой регистрации.
  Регистрация: отображаемое имя и пароль 12–256 символов. Вход поддерживает
  старые пароли. Лимиты: 10 попыток на операцию/логин/peer и 100 на peer за 15 мин.
- Частичная регистрация: браузер хранит случайный ID попытки (без пароля) в
  sessionStorage. Уникальная запись `registration_jobs` создаётся до Matrix.
  При повторе того же запроса после потери ответа сервер выполняет вход с
  переданным паролем, возвращая тот же MXID/device ID; register не повторяется.
  Другой ID попытки для занятого/создаваемого логина получает 409. Пароли в
  журнале заданий отсутствуют. Если создание осталось неопределённым и вход
  ещё невозможен, сервер сообщает конфликт и не перезаписывает учётные данные.
  При остановке процесса между резервированием и отправкой Matrix запроса
  может потребоваться ручная сверка зависшего задания администратором;
  автоматического удаления неопределённых заданий нет.
- Выход вызывает реальный Matrix logout; UI и SDK останавливаются после
  подтверждения сервера. Ключи не удаляются; сохраняется метаинформация устройства
  без токена. Повторный вход использует то же устройство/локальное хранилище.
  После сверки Ed25519/Curve25519 с Rust повторно публикуется сохранённый
  подписанный публичный device_keys через штатный SDK keys/upload: logout
  удаляет его на homeserver. Приватные ключи не извлекаются и подписи не
  подделываются. Живой тест проверяет новые сообщения в обе стороны после
  повторного входа, а не только чтение старой истории.
- Завершение остальных устройств — Matrix delete_devices с парольной UIA;
  смена пароля — account/password с UIA и logout_devices=true. Текущий сеанс
  сохраняется, остальные отзываются. Сервер проверяет whoami для защищённых API;
  клиентский userId и x-presidium-user-id не являются авторизацией. Прежний
  продуктовый action=revoke, который оставлял Matrix-токен рабочим, отклоняется
  публичным API с 410; UI использует только настоящий отзыв Matrix-устройств.
- Matrix проходит через единый `/_matrix` proxy с сохранением конечного `/`
  у протокольных URL (обычный rewrite ломал pushrules/). Прямые изменения
  учётных данных через proxy запрещены, включая URL-кодированные пути;
  регистрация/вход выполняются через ограниченную серверную границу. Для
  авторизованных Matrix-запросов сервер проверяет срок/отзыв токена, после
  чего сам homeserver проверяет право на конкретную операцию. Cookie в
  Matrix proxy не передаётся, используется только SDK Authorization.
- Автоматическая проверка сессии останавливает удалённо отозванный клиент.
  Экран авторизации не монтирует приватный интерфейс до bootstrap. Смена аккаунта
  перемонтирует основной UI, межвкладочное событие останавливает старую сессию.

## Запуск

Из корня репозитория:

```powershell
cd presidium
docker compose up -d tuwunel
.\.venv\Scripts\python.exe scripts/run-local.py
```

ПК: `http://127.0.0.1:5173`. Это исходный origin установленных локальных данных.
Для проверки используйте два независимых профиля/контекста браузера, а не две
обычные вкладки с общими cookie.

Для LAN (текущий Wi-Fi IPv4 ПК — 172.20.10.6; при смене сети уточнить ipconfig):

```powershell
.\.venv\Scripts\python.exe scripts/run-local.py --lan-host 172.20.10.6
```

Для уже собранной production-версии добавьте `--production`:

```powershell
.\.venv\Scripts\python.exe scripts/run-local.py --production --lan-host 172.20.10.6
```

Запускайте этот режим после остановки прежнего launcher, чтобы Next получил
`PRESIDIUM_PUBLIC_ORIGIN=https://172.20.10.6:5443`. На втором устройстве в той же
сети: `https://172.20.10.6:5443`. Прокси слушает только указанный частный IP;
Matrix/API остаются на loopback, интернет-туннелей нет.

При первом запуске создаётся локальный CA в `.cache/lan-tls`. Доверить публичный
`local-ca.crt` на тестовых устройствах (iOS: установка профиля + полное доверие
сертификату; Android/Windows: доверенные центры сертификации). Сверить SHA256 с
выводом launcher. Закрытые `.key` остаются на ПК. Обход ошибки сертификата не
заменяет доверенный HTTPS/secure context. Доступ через firewall и физический
телефон требуют отдельной проверки на устройстве пользователя.

Другой origin имеет другую IndexedDB: старые ключи из http://127.0.0.1:5173
автоматически на LAN origin не переносятся. Не очищайте прежние данные браузера.
Восстановление ключей на новом устройстве и cross-signing ещё не подключены;
предупреждение об этом показывается до выхода. Без ключей старые события могут
оставаться зашифрованными. Проверка доверия не отключается ради тестов.

## Файлы и проверки

Основные изменения: `features/auth.py`, `api.py`, Next `/api/auth/[action]`,
`/api/session`, `lib/local-matrix.ts`, существующий `MatrixTransport.ts`,
`auth-boundary.tsx`, `local-matrix-login.tsx`, `account-security.tsx`,
`account-manager.tsx`, `presidium-workspace.tsx`, `storage.ts`, `presidium.ts`,
`commissionka-local.ts`, `app/page.tsx`,
`app/auth.css`, `request-origin.ts`, `next.config.ts`, `scripts/lan_https.py`,
`scripts/run-local.py`, `argon/runtime.ts` (ключ зеркала сеанса включает токен,
поэтому повторный вход не наследует отозванную продуктовую сессию).

Итоговая проверка на production frontend:

- `npm run build`: успешно, включая обе проверки TypeScript и Next production.
- `npm test`: 10/10; `npm run test:argon`: 1/1 (финансовые регрессии).
- Python: 17/17 релевантных серверных проверок (4 живых auth + 13 существующих
  продуктовых/регрессионных/Matrix). После запрета старого неполного отзыва
  через `/api/account` четыре живых auth-теста повторно прошли.
- `npm run test:e2e`: 4/4, 0 flaky, 0 skipped, 1.1 мин на итоговом прогоне.
  Использованы реальные Matrix, SQLite, Next и четыре изолированных Chromium
  контекста; сетевые ответы не подменялись.
- `npm run lint`: exit 0, остаются предупреждения исходных компонентов о хуках,
  ref и неиспользуемом коде; предупреждения не объявляются исправленными.
- HTTPS проверен с валидацией цепочки через созданный CA, без отключения TLS:
  главная, регистрация, профиль, bootstrap, Matrix whoami и выход — 200;
  повторное использование отозванного токена — 401; прямая регистрация через
  URL-кодированный Matrix-путь — 403. Cookie: Secure, HttpOnly, SameSite=Strict.

Живой браузерный сценарий проверил все 14 запрошенных этапов:
Alice/Bob регистрируются независимо, занятый логин (включая другой регистр)
и неверный пароль отклоняются; поиск по точному логину создаёт настоящий DM;
сообщения доставляются в обе стороны, сырое событие — m.room.encrypted без
открытого текста. Перезагрузка сохраняет сессию, device ID и историю; серверные
события не дублируются. Выход отзывает Matrix-токен и серверный доступ, «Назад»
не открывает приватный UI. Bob в том же контексте не видит личную переписку,
заметку и файл Alice; повторный вход Alice восстанавливает данные и позволяет
снова обмениваться новыми сообщениями. Второе устройство Alice имеет другой
ID, отправляет сообщения Bob и получает ответы одновременно с первым.
Публичный Ed25519 сравнивается с keys/query на сервере. Отзыв другого устройства
и смена пароля закрывают его доступ; текущий сеанс сохраняется, старый пароль
перестаёт работать. Подстановка x-presidium-user-id/userId не даёт доступа к
профилю Bob, чужая комната Matrix отвергает третьего пользователя (403).

Существующие сценарии также проходят: группы, восстановление после разрыва
сети, локальные страницы Capsule, оригинальная навигация desktop/mobile и
загрузка ресурсов. Новый локальный файл проверяется через настоящий интерфейс
Библиотеки Capsule и чтение сохранённых байтов после повторного входа.

Доказательства (без паролей/токенов):
`presidium/.cache/auth-browser/final-results.json`, `evidence.json`,
`https-evidence.json`, PNG в том же каталоге; снимки оригинальных экранов —
`presidium/.cache/frontend-correction-browser/`. Физический телефон не был
доступен; межустройственный браузерный тест выполнен изолированными контекстами
на ПК. Доступ телефона через его firewall/сеть и доверие CA ещё нужно проверить
на самом устройстве.

Локальное хранение: владелец состояния определяется только подтверждённой
сессией в памяти; значение localStorage не даёт доступа к чужой области.
Новые blobs и вспомогательный ECDSA-ключ подписи имеют namespace MXID.
Совместимость старых глобальных файлов разрешает чтение через уже принадлежащие
аккаунту записи. Неопределённые старые файлы/ключи и анонимные записи сохранены
без автоматического присвоения следующему пользователю. Удаление новых файлов
не стирает неоднозначные legacy-копии. Это изоляция приложения; общий профиль
браузера/доступ к DevTools не заменяет защиту ОС. Для независимых пользователей
на общем ПК используйте отдельные профили браузера.

Источники протокола: [Matrix password management](https://spec.matrix.org/latest/client-server-api/#password-management),
[Matrix logout](https://spec.matrix.org/latest/client-server-api/#post_matrixclientv3logout),
[настройки Argon2id Tuwunel](https://github.com/matrix-construct/tuwunel/blob/main/tuwunel-example.toml).
Реализация и реальные ответы проверены на локальном Tuwunel 1.9.3.
